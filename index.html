How CryptoVault Works

CryptoVault manipulates images at the raw pixel level — each RGBA pixel value is transformed through mathematical operations that are only reversible with the correct key.

01
⊕
XOR Cipher

Each pixel channel is XOR'd with a pseudo-random byte derived from your key using a Linear Congruential Generator. XOR is self-inverse — applying it twice with the same key restores the original.

out[i] = pixel[i] XOR keystream[i]
02
+
Caesar Shift

Derived from the classical Caesar cipher. Each channel (R, G, B) receives a different offset based on the key hash. Decryption subtracts the same offset modulo 256.

out[R] = (pixel[R] + offset) mod 256
03
↔
Channel Swap

One of 6 possible RGB permutations is selected based on the key hash. The channels are shuffled — turning red skies cyan, green grass purple, and so on.

[R,G,B] → permutation(key)[R,G,B]
04
↺
Bit Rotation

Each byte in each channel is rotated left by N bits (where N is derived from the key, 1–7). Unlike shifts, no bits are lost — rotation is perfectly reversible by rotating right N bits.

out = rotl(pixel, N) → rotr(out, N)
05
⚡
Block Scramble

The image is divided into 16×16 pixel blocks. A seeded Fisher-Yates shuffle rearranges the blocks pseudo-randomly based on the key. The inverse permutation restores order.

blocks[order[i]] ↔ blocks[i]
06
🔐
Combined (Max Security)

Chains XOR + Caesar Shift + Channel Swap in sequence, each with a key-derived variant. Decryption applies the inverse operations in reverse order for perfect reconstruction.

E(x) = Channel(Shift(XOR(x)))
Important: Always download as PNG (lossless). JPEG compression alters pixel values — decryption will fail on a JPEG-re-encoded image.
